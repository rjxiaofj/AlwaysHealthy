# 登录页身份切换时的布局抖动

## 前置影响分析（AGENTS.md 第 7 节）

改动文件：

- `frontend/src/views/LoginView.vue`：卡片固定高度与 flex 列布局、标题/副标题/错误行/底部说明等高占位、提交按钮贴底、底部说明改为常驻 computed。
- `frontend/src/views/LoginView.spec.ts`：新增 3 条布局稳定回归。
- 不改后端、不改路由、不改认证逻辑、不加依赖、不动数据库。

公共方法依赖：

- `useAuthStore` 的 `login` / `register` / `pending` 不变；`switchTab`、`toggleMode`、`submit` 的行为不变。
- `api/client.ts`、`utils/redirect.ts`、`styles/tokens.css` 都不改。选项卡的 `.segment-item` 过渡只作用于自身背景与文字色，不影响布局。

受影响旧模块：

- 列表 / 定时任务 / 报表 / 工作流节点：全部无。登录页不读业务接口。
- 登录链路：只改 DOM 结构与文案容器，请求参数（`expected_role`、`role`、`admin_code`）、跳转与错误展示原样保留，已有 11 条用例继续把守。

权限与数据范围检查：

- 无新增接口、无新增查询，不需要补 `user_id` 条件或角色判断。
- 身份选项卡仍只是前端通道选择，后端按库里的 `User.role` 校验；本次不碰这条边界。
- 底部说明改为两种身份各一句，都是静态文案，不含账号或健康数据。

回归用例：

- T-新增 `LT-12~14`：卡片固定高度、切换身份不增删节点、错误行常驻、从管理员注册切回用户登录不残留节点。
- R-关联：原有 `LT-01~11` 全量重跑（选项卡文案、请求参数、跳转、邀请码、后端错误文案）。
- E-全链路：真浏览器打开 `/login`，量「用户登录 → 管理员登录 → 管理员注册 → 切回用户登录」四态的卡片、提交按钮、底部说明位置与内部滚动高度；再在 390x844 手机视口重复。

## 问题

用户反馈「点击用户和管理员登录的时候，页面会动态变化」。登录页外层是 `min-h-screen items-center justify-center`，卡片高度由内容撑开；切换身份时：

- 底部说明 `<p v-if="isAdminTab">` 只在管理员态出现，增减约 26px；
- 错误提示 `<p v-if="error">` 出现或清空时增减一行；
- `switchTab` 会把注册态收回登录态，管理员注册表单的邀请码块整块消失。

卡片一变高，垂直居中就会把整张卡片上下各推一半，看起来像整页在跳。

## 方案

| 决策 | 做法 | 理由 |
| --- | --- | --- |
| 卡片尺寸 | 固定 `h-[664px]`，`max-h-[calc(100vh-3rem)]` + `overflow-y-auto` 兜小视口 | 高度不随内容变，垂直居中就不会把页面推来推去 |
| 可变区域 | 标题 `min-h-[26px]`、副标题 `min-h-[36px]`、错误行 `min-h-[18px]`、底部说明 `min-h-[34px]` 全部常驻占位 | 文案长度或换行差异不再改变高度 |
| 底部说明 | 去掉 `v-if`，改 `footerNote` computed，两种身份各一句 | 节点不再增删，身份信息仍保留 |
| 提交按钮 | `form` 用 `flex-1`，按钮 `mt-auto` 贴底 | 邀请码块出现/消失时按钮位置不变 |
| 邀请码说明 | 缩短成一行 | 给固定高度留余量，也去掉对用户无意义的环境变量名 |

`664px` 是按最大态（管理员注册，3 个输入 + 说明）实测出来的：第一版设 `620px` 时 `scrollHeight 655 > clientHeight 618`，提交按钮被推到滚动区外，属于本轮修复自己引入的回归，已在浏览器里发现并修正。

自动化：后端 **331 passed**、前端 **223 passed**（22 个文件，`LoginView.spec.ts` 11 → 14 条），`vue-tsc` / `vite build` / `npm run size` 全绿（首屏 50.3/58 kB、totalJs 90.4/100 kB）。容器已用 `up -d --build` 重建，验证的是真部署产物而不是 dev server。

## 残留取舍

1. 固定高度换取稳定位置，代价是登录态卡片里有一段空白，靠 `mt-auto` 把提交按钮推到底部形成上下分区。
2. 视口高度低于 `664px + 3rem` 时 `max-h` 生效，卡片内部可滚动；极窄屏上管理员注册态仍需滚动一点才能看到按钮。
3. 两种身份的文案差异（标题、副标题、按钮、底部链接、说明）仍然保留：那是管理员通道的辨识信息，本次只消除它们引起的**布局**变化。若产品上希望连文案也固定，需要另做一轮取舍。

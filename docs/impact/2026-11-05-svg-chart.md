# 影响分析：趋势图改手写 SVG，去掉 echarts

日期：2026-11-05

## 背景

上一次已经把这个图改成按需加载，没有指标的新账号不再下它。但包还在：466.48 kB（gzip 157.25），而两张图要的东西只有「一条折线、一套虚线网格、一个悬停提示」。

这页的数据形状很简单——`MetricPoint[]`，一条线，最多几十个点。为这点东西背一个完整图表库，收益全在没用的功能上（多坐标系、图例、缩放、动画）。

## 做法

拆成两层：

**`components/chartGeometry.ts`**：只做「值 → 屏幕坐标」，输出路径字符串与刻度数组，不碰 DOM。

- `niceDomain`：纵轴按 1 / 2 / 2.5 / 5 / 10 的整数倍取刻度，不会出现 0.3333 这种读不出来的数。只有一次测量时上下各撑 10%，否则整条线贴在画布边上。
- 平滑用**单调三次贝塞尔**（Fritsch–Carlson），不是 Catmull-Rom。普通样条会在两个相近测量值之间鼓出比原始数据更高的峰，指标图上等于凭空画出一个没测到过的值。横血压这种数据上这是错误陈述，不是审美问题。
- 横轴标签按 `plotWidth / 56` 抽稀，首尾一定保留（末尾是最新一次测量）。首尾用 `start` / `end` 锚点，贴边不被裁。
- `nearestIndex`：悬停时取横坐标最近的点。

**`components/TrendChart.vue`**：把上面算出的数字拼进 SVG，`ResizeObserver` 跟住容器宽度重算（SVG 不像 canvas 能整体缩放，坐标得按真实像素算）。颜色全走 CSS 变量 + `currentColor`，深浅主题不用在脚本里判断。

## 视觉与交互保持

| 能力 | 原来（echarts） | 现在 |
|---|---|---|
| 折线平滑 | `smooth: 0.3` | 单调三次贝塞尔，且不过冲 |
| 面积渐变 | `LinearGradient` 0.16 → 0 | `<linearGradient>` 同参数 |
| 虚线网格 | `splitLine type: dashed` | `stroke-dasharray: 4 4` |
| 悬停提示 | `tooltip trigger: axis` | 最近点 + 垂直参考线 + 玻璃拟态浮层 |
| 主题 | 脚本里判断 `theme.mode` 取两套色 | CSS 变量自动跟随 |

提示框位置做了两处防遮挡：靠左右边时向内收，点靠近顶部时翻到下方——最高点上方正好是指标切换栏，压上去会挡住可点的按钮。

## 结果

| | 改动前 | 改动后 |
|---|---|---|
| 图表运行时 | echarts 466.48 kB（gzip 157.25） | 5.85 kB（gzip 2.77） |
| 首屏 JS | 约 129 kB（gzip 50.6） | 116.07 kB（gzip 45.43） |
| 加载方式 | `defineAsyncComponent` + 260px 占位 | 静态引入，不再需要占位 |
| 依赖 | `echarts ^5.6.0` | 无 |

按需加载也一并撤回：几 kB 的组件再拆一个请求不划算，`min-h-[260px]` 占位与相关注释一起删掉。

新增 18 条几何用例（`chartGeometry.spec.ts`），覆盖单点居中、刻度包住数据、曲线过首尾、**不过冲**、横轴抽稀、非有限值过滤、提示框选点。前端 115 → 133 项。

## 取舍

echarts 能给的动画、缩放、多序列叠加现在都没有了。这份数据只有一条线，暂时不需要；真要加第二条线得自己扩 `chartGeometry`，那时可以考虑再引库。

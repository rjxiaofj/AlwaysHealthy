# 提醒按设定时间到点才催

## 问题

计划的每个任务都带 `scheduled_time`（模板里如 08:00 测血压、20:30 记录饮食、22:00 睡前少屏幕），但 `reminder_service.sync` 生成「今日任务待完成」提醒时完全没用这个时间——一天里的任何时刻，只要任务还没打卡，就会顶一条「待完成」。早上六点打开 App，会被提醒「晚上十点睡前少屏幕」这条还没到时间的事，既不准确也烦人。

## 改动

`reminder_service.sync` 里给「待完成」提醒加一道时间闸：

- 新增 `_time_passed(scheduled_time, now)`：任务没有 `scheduled_time`、或当前时刻已过设定时间，才算「到点」。`scheduled_time` 是 `HH:MM` 字符串，与东八区 `business_now()` 比较。
- 未到点的任务跳过生成提醒（`continue`），到点后才生成。
- 到点的提醒在 `content` 里带上时间提示：`记录三餐与含糖饮料（设定时间 20:30），完成标准：…`，让用户知道「几点该做什么」，而不是笼统的「今日任务待完成」。

`timeutil.py` 新增 `business_now()`，返回东八区当前时刻，与 `business_today()` 同口径（容器默认 UTC，早上 0~8 点服务器还停在前一天，不用东八区会整体错一天）。

## 边界

- `_time_passed` 对坏格式时间（`25:00`、`abc`、空串）退回到「已到点」，避免一个坏数据卡住整条提醒链路。
- 分钟边界是包含的：08:00 的任务在 08:00 整就算到点，不是 08:01 才到。
- 计划级的 `task_overdue`、`plan_end` 两条提醒不走时间闸（它们跟「是否到点」无关，跟「有没有遗漏」「周期是否收尾」有关）。

## 验证

| 编号 | 输入 | 期望 |
|---|---|---|
| TG-01 | `None` / 空串 scheduled_time | 已到点 |
| TG-02 | 22:00 任务、当前 06:00 | 未到点 |
| TG-03 | 08:00 任务、当前 08:00 / 08:30 / 23:00 | 已到点（边界含） |
| TG-04 | `25:00` / `abc` | 退回到已到点 |

`test_reminder_switch.py` 加 autouse fixture 把 `business_now` 钉在 23:59（晚于所有模板时间），否则「今日任务数 == 提醒数」这类断言会在早上运行时飘。后端 270 → 275 项。

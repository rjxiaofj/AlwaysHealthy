# 影响分析：业务日期按东八区算，以及表单里看不到的年龄

日期：2026-11-05

## 一、业务日期

### 问题

前后端都在用 UTC 的「今天」。

前端两处：`DashboardView` 的今日任务用 `new Date().toISOString().slice(0, 10)`，`PlansView` 的 `today` 同款写法。`toISOString` 走 UTC，东八区凌晨 0 点到 8 点之间它给出的是前一天。

后端十四处 `date.today()`，容器默认 UTC，同样在凌晨 0 点到 8 点这段时间停在前一天。

后果集中在每天这八小时：

| 位置 | 表现 |
|---|---|
| 首页今日任务 | 空列表，因为拿昨天的日期去比今天排的任务 |
| 计划页距结束天数 | 多一天，`canReassess` 的「只剩两天」判断跟着偏 |
| 计划页改期最小日期 | 差一天，可以选到后端认为的「昨天」 |
| 后端打卡日期 | `checkin_date` 落到前一天，同一天打两次会变成两条 |
| 每日任务提醒 | 生成给前一天的日期，当天任务不提醒 |

### 修法

前端新增 `src/utils/datetime.ts`：`localToday`、`localDateTimeInput`、`localDateInput`。偏移量可以显式传入，测试里给 `-480` 就能固定成东八区，不依赖跑测试的机器。

后端在 `app/core/timeutil.py` 加 `BUSINESS_TZ`、`to_business_date`、`business_today`，替换十四处 `date.today()`。用固定 +8 而不是 `ZoneInfo("Asia/Shanghai")`：中国没有夏令时，固定偏移足够，而且不依赖镜像里装没装 tzdata（`python:3.13-slim` 不保证有）。

测试里 23 处 `date.today()` 同步换成 `business_today()`，两边口径一致，CI 跑在 UTC 也不会出现「后端说是 5 号、用例期望 4 号」。

顺带清掉三个因为替换而失效的 `from datetime import date`。

### 为什么不用 TZ 环境变量

给容器加 `TZ=Asia/Shanghai` 是更短的路，但有两个不确定：slim 镜像不一定有 tzdata，缺了会静默退回 UTC，看起来改了其实没改；而且这只影响部署形态，本机直接跑 uvicorn 的环境仍然各按各的。固定在代码里的偏移没有这两个问题。

代价是这套逻辑默认用户在东八区。急救电话默认 120、文案是中文，这个假设与产品一致；真要支持其他时区，得把偏移做成配置项，不是这轮的范围。

## 二、表单里看不到的年龄

聊天里只说了「我 38 岁」时，后端把年龄写进 `age_years`，`birth_date` 留空。表单只编辑 `birth_date`，所以这个年龄在个人中心完全看不到，用户会以为自己没填过。

`get_profile` 返回的 `age` 是 `age_of(birth_date) or age_years`，两条来源合成一个值。前端靠 `birth_date` 有没有值就能判断来源，不需要后端多返回字段。

新增 `ageSource(profile)`，在出生日期输入框下面显示一行：

- 没有年龄：`填写出生日期后自动计算年龄`
- 有生日：`36 岁 · 按出生日期计算`
- 没生日但对话里报过：`38 岁 · 来自对话中提到的年龄，补充出生日期可以更精确`

没有改后端，也没有加写入路径。允许用户直接编辑年龄会引入「生日与年龄两个来源打架」的新问题，等真有需求再说。

## 三、顺带修的

`TrendsView` 的测量时间框被清空后，`new Date('').toISOString()` 抛 `RangeError`，用户会在提示里看到英文「Invalid time value」。现在先校验再提交，提示「选择测量时间」。

## 影响面

| 范围 | 是否受影响 | 说明 |
|---|---|---|
| 日期比较口径 | 是 | 前后端统一按东八区 |
| 历史数据 | 否 | 不涉及迁移，已存的 DATE 值不变 |
| 接口形状 | 否 | 无字段增减 |
| 跨时区用户 | 是（已知限制） | 非东八区用户看到的「今天」会是东八区的今天 |
| 前端新增文件 | 是 | `src/utils/datetime.ts` |

## 验证

- `pytest` 172 项通过（新增 6 项时区用例）。
- 前端 66 项通过（新增 8 项日期用例、3 项年龄用例）。
- `vue-tsc --noEmit` 与 `npm run build` 通过。
- 时区用例显式传偏移，跑在 UTC 的 CI 上也能证明实现走的是东八区而不是 UTC：`2026-11-04T17:30Z` 在 UTC 下是 11-04，期望 11-05。

## 遗留

- 固定在代码里的 +8 是产品假设，不是通用能力。要支持其他时区得做成配置。
- 首页的 `todayTasks` 是 computed，跨零点不会自己刷新，得等页面重新加载。这是既有行为，没动。
- `PlansView` 的 `today` 是 setup 时算一次的常量，长时间挂着页面同样会跨天不更新。

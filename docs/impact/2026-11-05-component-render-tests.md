# 影响分析：组件渲染测试起步

日期：2026-11-05

## 为什么是现在

`MEMORY.md` 的「已知取舍」里一直写着「组件本身没有渲染测试」。判定与请求体拼装这类分支早就抽成纯函数覆盖了，剩下的空档是「算出来的数字有没有真的变成 DOM」——这次把图表换成手写 SVG，正好是这一类：几何层有 18 条用例，但没人验证过这些路径真的被渲染出来、悬停真的会出提示。

## 做法

引 `@vue/test-utils`（`happy-dom` 环境本来就有），只给 `TrendChart` 写 6 条：

| 编号 | 断言 |
|---|---|
| RT-01 | 没有数据时显示「暂无可画的数据」，不渲染 `<svg>` |
| RT-02 | 3 个测量点 → 3 个 `<circle>`，`path.chart-line` 的 `d` 以 `M … C` 开头 |
| RT-03 | `svg[width]` 等于容器实测宽度，最后一个点贴在右侧留白处 |
| RT-04 | `pointermove` 到中间点 → 提示框出现且含日期、数值、单位；`pointerleave` 后消失 |
| RT-05 | 鼠标在最左边时提示框向内收，`left ≥ 64`，不会被容器切掉 |
| RT-06 | 所有坐标标签的 `y` 都落在画布内 |

`happy-dom` 没有布局也没有 `ResizeObserver`，测试里塞一个 stub：`observe()` 时同步回调一个固定宽度 400。这样组件会按 400 走完整条「实测宽度 → 重算坐标 → 重渲染」的路径，比自己 mock `clientWidth` 更接近真实行为。

## 验证

变异：把 `buildChart` 的宽度从 `width.value || 640` 改成写死 `640`，RT-03 挂；复原后全绿。前端 135 → 141 项。

## 取舍

- 只覆盖了图表这一个组件。聊天页（流式渲染、确认卡片、滚动到底）、计划页（草稿增删）仍然没有渲染测试——它们的逻辑分支已经抽成纯函数（`planLogic.ts`、`profileLogic.ts`），剩下的主要是模板与事件接线，等这两处再改时顺手补。
- stub 掉 `ResizeObserver` 等于放弃「窗口缩放后重算」这条路径的验证。真验需要真实布局引擎，happy-dom 给不了。
- 样式没有断言（颜色、间距、玻璃拟态），那些靠截图看。

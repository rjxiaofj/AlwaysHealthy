# 影响分析：跨零点自动翻页、输入法回车不再误发送

日期：2026-11-05

## 一、页面挂着过零点不刷新

`DashboardView` 的今日任务在 computed 里现算日期，`PlansView` 的 `today` 是 setup 时算一次的常量。两者在跨零点后都不会更新：页面开一晚上，第二天早上看到的还是昨天的任务列表，计划页的「今天」高亮也停在昨天。

### 做法

新增 `src/utils/today.ts`，导出 `useToday()`，返回一个 `ComputedRef<string>`：

- 模块级单例，多个页面共享同一份日期，不会各自起一个定时器。
- 三十秒对一次 `localToday()`，值变化才写入，没跨天不触发重渲染。
- 同时监听 `visibilitychange`：后台标签页的定时器会被浏览器节流到一分钟以上，切回来要立刻对齐。
- 引用计数：第一个挂载时启动，最后一个卸载时停。不常驻。
- 第一个使用者进来先同步一次，避免沿用上一次挂载留下的旧值。

三十秒的代价可以算清楚：一天 2880 次字符串比较，跨零点后最多晚半分钟翻页。比监听系统时钟变化简单，也不用处理时区切换。

`DashboardView` 与 `PlansView` 改用 `useToday()`。`PlansView` 里 script 中的两处（`canShiftPlan`、`daysUntil`）要取 `.value`，模板里由 Vue 自动解包，不用改。

### 测试

用 `vi.useFakeTimers()` 加 `vi.setSystemTime()` 控制时钟，`effectScope` 模拟组件生命周期：

| 编号 | 场景 | 期望 |
|---|---|---|
| CD-01 | 23:50 挂载 | 日期是当天 |
| CD-02 | 23:59:40 挂载，推到 00:00:10 再走 30 秒 | 日期翻到第二天 |
| CD-03 | 8:00 挂载，走 60 秒 | 日期不变 |
| CD-04 | 两个使用方 | 拿到同一个 ref，只起一个定时器 |
| CD-05 | 依次卸载 | 只剩一个时定时器还在，全卸载后清零 |
| CD-06 | 卸载后改系统时间再挂载 | 立即对齐到新日期，不沿用旧值 |

## 二、输入法选词时按回车会直接发送

`ChatView` 的输入框绑的是 `@keydown.enter.exact.prevent="send"`。中文输入法在组字状态下按回车是选词，但 `keydown` 一样会触发 `key === 'Enter'`，于是这一下既被 `preventDefault` 打断了选词，又把半截输入发了出去。

改成 `@keydown="onKeydown"`，由 `shouldSubmitOnEnter()` 判断：`key` 是 Enter、没有按 Shift、`isComposing` 为假，三者都满足才拦默认行为并发送。判断放在 `preventDefault` 之前，组字时的回车留给输入法。

逻辑抽到 `src/utils/keyboard.ts`，五条用例覆盖普通回车、Shift 回车、组字回车、其他按键。

## 三、顺带

`AssessmentView` 点历史评估调 `assessmentApi.detail`，没有 try/catch。那条记录被清理后点一下没有任何反应，只在控制台留一条未处理的 promise 拒绝。补上提示。

## 影响面

| 范围 | 是否受影响 | 说明 |
|---|---|---|
| 接口 | 否 | 只改前端 |
| 定时器 | 是 | 新增一个 30 秒间隔的定时器，最多一个，最后卸载时清除 |
| 输入行为 | 是 | 组字状态下回车不再发送 |
| 其他页面 | 否 | `useToday` 只有首页与计划页在用 |

## 验证

- 前端 `npm test` 77 项通过（新增 6 项跨零点、5 项回车判断）。
- `vue-tsc --noEmit` 与 `npm run build` 通过。
- 后端无改动。

## 遗留

- 定时器只解决「日期变了」。如果页面上的任务数据本身过期（比如别人在另一端改期），仍然要等用户操作触发重新加载。
- 三十秒是固定间隔，没有对齐到零点整。想更准可以在 `sync` 里算出距下一个零点的毫秒数再用 `setTimeout`，但收益只有半分钟，不值得多一层状态。

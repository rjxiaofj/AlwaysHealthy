# 影响分析：流式请求的切帧、续期与错误提示

日期：2026-11-05

## 一、切帧逻辑不可测，且 CRLF 会整条流丢事件

`api/stream.ts` 里原来把「读流、拼缓冲、切事件、解析 JSON」写在一个 while 循环里。这套逻辑有三个地方只能靠真实流才能验，写在组件里就永远没有单测：

1. 事件之间用 `\n\n` 分隔。若上游把它变成 `\r\n\r\n`（某些代理会改换行），`indexOf('\n\n')` 一个都找不到——`\r\n\r\n` 里没有两个相邻的 `\n`——整条流一个事件都不出来，`buffer` 一直涨到流结束才停。
2. 半个事件跨在两个 chunk 之间要留在缓冲区。
3. 多行 `data:` 要按规范用 `\n` 拼回去。

### 做法

新增 `src/utils/sse.ts`，两个纯函数：

```ts
splitSseFrames(buffer): { frames: SseFrame[]; rest: string }
parseSseFrame(block): SseFrame
```

`splitSseFrames` 先 `replace(/\r\n/g, '\n')` 归一化再切，最后一段不完整的留在 `rest`。`readStream` 只负责读、解、派发。

## 二、聊天请求不续期

`api()` 有 401 → 刷新 → 重放的逻辑，但 `postStream()` 走的是裸 `fetch`，没有这层。访问令牌有效期 120 分钟，用户挂着页面聊天，过了两小时发出的消息会直接失败，而同一个页面上的其他请求都能自动续期。

现在 `postStream` 遇到 401 先调 `refreshSession()`（`client.ts` 新导出，复用模块级 `refreshTask`，并发请求仍只刷一次），成功就重放整条流。流在 401 时还没有任何事件发出，重放不会产生重复消息。

## 三、错误提示原样吐 JSON

`readStream` 原来 `throw new Error(text)`，`text` 是后端的 `{code, message, ...}` 包体。用户会在聊天气泡里看到一串 `{"code":"AUTH_UNAUTHORIZED","message":"…","request_id":"…"}`。

改成先尝试按 JSON 解析取 `message`，取不到再用原文，都没有就退回 `请求失败 {status}`。与 `api()` 的错误口径一致。

## 四、顺带：趋势页左栏被拉长

`TrendsView` 的两栏 grid 没写 `items-start`，左栏图表卡片被右栏（录入表单加感受列表）撑到同样高，图表下面空出一大块。加 `items-start` 后卡片回到内容高度。

## 测试

新增 `src/utils/sse.spec.ts` 8 项、`src/api/stream.spec.ts` 6 项：

| 编号 | 场景 | 期望 |
|---|---|---|
| SS-01 | 一次到达两个完整事件 | 切出两条，`rest` 为空 |
| SS-02 | 第二个事件只到了一半 | 只切出第一条，剩下半截留在 `rest` |
| SS-03 | `\r\n\r\n` 分隔 | 仍能切出事件 |
| SS-04 | 多行 `data:` | 用 `\n` 拼回一个字符串 |
| SS-05 | 没有 `event:` | 按 `message` 处理 |
| SS-06 | 只有空行的块 | 不算事件 |
| SS-07 | 分片到达（一半 JSON 在第二片） | 两次 read 后拿到两条完整事件 |
| SS-08 | `data` 不是合法 JSON | 回调收到 `{raw}` |
| SS-09 | 401 且续期成功 | 重放一次，令牌换成新的，事件照常派发 |
| SS-10 | 401 且续期失败 | 抛出后端的中文 message，不是整段 JSON |
| SS-11 | 409 业务错误 | 同样用后端 message |
| SS-12 | 错误体不是 JSON | 退回 `请求失败 502` |

变异验证两处：去掉 CRLF 归一化，SS-03 红；把 401 分支短路，SS-09 红。复原后前端 103 项全绿。

端到端另验了一次：起本地服务，浏览器里新建对话发一句「我最近睡眠不太好」，25 秒后回复完整显示，底部医学依据正常（截图 `06-chat-stream.png`）。这条走的是真实 DeepSeek 调用与真实 SSE。

## 影响面

| 范围 | 是否受影响 | 说明 |
|---|---|---|
| 接口 | 否 | 后端没动 |
| 聊天 | 是 | 令牌过期时会先续期再发，不再直接失败 |
| 错误文案 | 是 | 从原始 JSON 变成后端 message |
| 其他请求 | 否 | `api()` 逻辑没动，只多导出一个 `refreshSession` |
| 趋势页 | 是 | 左栏卡片不再被拉长 |

## 遗留

- 重放只处理 401，其他错误（500、网络断）不重试。健康咨询是长耗时请求，自动重试有重复生成回复的风险，留给人点重发。
- `readStream` 仍然没有超时。后端挂着不回时前端会一直等，要停只能靠 `AbortSignal`，目前 `ChatView` 也没传 signal。这一层要么在后端加心跳超时，要么在前端加空闲计时，两者都没做。
- 流结束时若最后一个事件没有以空行收尾，那一帧会被丢掉。当前后端每条事件都带 `\n\n`，实际不会触发；真遇到需要在 `done` 之后把 `rest` 再切一次。
